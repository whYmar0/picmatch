# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ПРОМПТ ДЛЯ РЕАЛИЗАЦИИ): Оптимизация производительности VotePage, устранение фантомных свайпов при зуме и исправление анимации комментариев

## 1. ЦЕЛЬ И ЗАДАЧИ
Устранить критические проблемы UX и производительности на странице голосования (`VotePage.jsx`), сделав интерфейс плавным (стабильные 60–120 FPS на мобильных устройствах при 4x/6x CPU Throttling и в альбомах на 50+ тяжелых фото), исключить ложные голосования при использовании щипка (pinch-to-zoom) и обеспечить отзывчивую анимацию шторки комментариев без просадки кадров.

---

## 2. КОРНЕВЫЕ ПРИЧИНЫ НЕИСПРАВНОСТЕЙ (ROOT CAUSE ANALYSIS)

### 2.1. Лаги, статтеры и падения FPS
1. **Непрерывный ререндер через useState:** В `SwipeCard.jsx` координаты пинча обновляются через `useState` (`pinchTransform`). При каждом событии `touchmove` (частота 60–120 Гц) происходит полный ререндер компонента React.
2. **Каскадный ререндер VotePage при перетаскивании:** При сдвиге карточки на 80px колбэк `onLikeThresholdCrossed` вызывает `setHearts`, заставляя перерисовываться весь `VotePage`, включая массив из 50 элементов в ленте миниатюр.
3. **50 экземпляров Framer Motion кнопок:** Лента миниатюр рендерит 50 компонентов `<motion.button>`. Инициализация и поддержание дерева жестов Framer Motion для 50 элементов перегружает процессор мобильного устройства.
4. **Слушатель visualViewport:** `viewport.addEventListener("scroll", updateViewport)` спамит вызовами `setViewportHeight`, вызывая ререндер дерева страницы при малейшем сдвиге экрана.

### 2.2. Баг ложного свайпа после щипка (Pinch-to-zoom)
1. В `SwipeCard.jsx` внешняя карточка `<motion.div drag={isTop && !pinchActive}>` начинает перехватывать жесты с первого пальца.
2. При отпускании одного из пальцев `handlePinchEndCapture` вызывает `finishPinch()`, обнуляя флаг активности пинча еще до того, как второй палец оторвался от экрана.
3. Оставшийся палец завершает жест через `handleDragEnd`, где Framer Motion берет накопленный `info.offset.x` от точки первоначального касания. Если фото было сдвинуто более чем на 64px, срабатывает условие `absX > SWIPE_THRESHOLD` и вызывается `onSwipe(photo.id, isLike)`.

### 2.3. Зависание и поломка анимации шторки комментариев
1. **Блокировка UI-потока декодированием растра:** В `topContent` шторки передается оригинальный URL стокового фото (`commentSheet.url`, 15–25 МБ) вместо легковесного превью (`thumb_url`, ~25 КБ). Браузер замирает на сотни миллисекунд для декодирования многомегабайтного растра ровно в момент старта анимации выезда.
2. **Принудительный Reflow на каждый кадр:** Параметр `resizeTopContentWithSheet` анимирует свойство `height` блока изображения через интерполяцию `topContentHeight`. Анимация геометрических размеров (`height`) провоцирует Layout Reflow на каждом кадре.
3. **GPU Overdraw от backdrop-blur-xl:** Полноэкранный фильтр `backdrop-blur-xl` без непрозрачной подложки накладывает колоссальную нагрузку на видеочип смартфона при трансформациях слоя.

## 3. ТРЕБОВАНИЯ К ДОРАБОТКЕ И АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### 3.1. Устранение ложного голосования и изоляция пинча (`SwipeCard.jsx`)
1. **Введение блокирующего тайм-аута и флагов:**
   - Создать `pinchActiveRef = useRef(false)`, `pinchOccurredRef = useRef(false)` и `pinchCooldownUntilRef = useRef(0)`.
   - При фиксации двух касаний устанавливать `pinchOccurredRef.current = true`.
   - При завершении пинча устанавливать `pinchCooldownUntilRef.current = Date.now() + 450` (кулдаун 450 мс, в течение которого любые свайпы жестко блокируются).
2. **Защита в `handleDragEnd`:**
   ```javascript
   const isPinchRestricted = 
     pinchActiveRef.current || 
     pinchOccurredRef.current || 
     Date.now() < pinchCooldownUntilRef.current ||
     pinchTransformRef.current.scale > 1.05;

   if (isPinchRestricted) {
     pinchOccurredRef.current = false;
     controls.start({ x: 0, y: 0, rotate: 0, transition: { type: "spring", stiffness: 350, damping: 28 } });
     return;
   }
   ```
3. **Отказ от useState для координат пинча:**
   - Использовать прямое мутирование стиля `pinchImageRef.current.style.transform = ...` либо привязать трансформацию к `useMotionValue`. Исключить ререндеры React в цикле `touchmove`.
4. **Сброс жеста drag во время масштабирования:**
   - При старте пинча вызывать `x.set(0); y.set(0); controls.stop();`.
   - Если масштаб `scale > 1.0`, перетаскивание одним пальцем должно панорамировать увеличенное изображение внутри карточки, а не перемещать саму карточку голосования.

### 3.2. Оптимизация производительности и устранение статтеров (`VotePage.jsx`)
1. **Мемоизация ленты миниатюр и замена `<motion.button>`:**
   - Вынести элемент миниатюры в мемоизированный компонент `ThumbButton = React.memo(...)`.
   - Заменить `<motion.button>` на нативный `<button>` с аппаратным CSS-классом `active:scale-95 transition-transform duration-150`.
   - Использовать `photo.thumb_url || photo.url` для всех превью ленты.
2. **Изоляция слоя HeartBurst от состояния VotePage:**
   - Вынести отображение сердец в обособленный контейнер с локальным управлением через ref-события или изолированный стейт, чтобы порог лайка не вызывал перерисовку всего дерева `VotePage`.
3. **Очистка слушателя visualViewport:**
   - Убрать слушатель `"scroll"` у `visualViewport`. Оставить только `"resize"` и `"orientationchange"`.

### 3.3. Исправление шторки комментариев (`BottomSheet.jsx` и `VotePage.jsx`)
1. **Использование легковесного превью в `topContent`:**
   - В блоке `topContent` страницы `VotePage.jsx` передавать `commentSheet.thumb_url || commentSheet.url`.
2. **Отказ от layout-анимации `height` в пользу `transform`:**
   - Исключить анимацию CSS-свойства `height` у `topContentHeight`.
   - Использовать масштабирование через `transform: scale(...)` и `translate3d`, исполняемые полностью на GPU без вызова Reflow.
3. **Смягчение эффекта размытия:**
   - Заменить тяжелый `backdrop-blur-xl` на `backdrop-blur-md` с умеренной темной подложкой `bg-black/50`, что снижает нагрузку на видеопамять мобильных устройств в 3–4 раза.
4. **Устранение гонки анимаций при закрытии (`deferClose`):**
   - Убедиться, что вызов `onClose` происходит строго по колбэку завершения анимации `onAnimationComplete`, предотвращая визуальные скачки и дублирование состояния.

## 4. МЕТОДИКА СТРЕСС-ТЕСТИРОВАНИЯ И ТРОТТЛИНГА

### 4.1. Конфигурация мобильного профиля (Mobile Emulation)
- **Устройство:** iPhone 13 / Pixel 7 (Viewport 390×844, DPR: 3.0, Touch Enabled: true).
- **CPU Throttling:** 4x Slowdown (эмуляция среднебюджетного мобильного процессора) и 6x Slowdown (эмуляция слабого устройства под нагрузкой).
- **Сеть:** Fast 3G / Slow 4G (Latency 150ms, Throughput 1.6 Mbps).

### 4.2. Сценарии тестирования (Test Cases)
1. **Стресс-тест щипка и панорамирования (Pinch-to-zoom Flaw Verification):**
   - Открыть альбом на 50 фото.
   - Выполнить 2-пальцевый жест pinch-zoom на верхней карточке с увеличением масштаба до 2.5x.
   - Сместить оба пальца по горизонтали на +120px вправо.
   - Оторвать один палец, затем через 50 мс оторвать второй палец.
   - **Ожидаемый результат:** Карточка плавно пружинит в центр `(x: 0, y: 0)`. Свайп не засчитывается, голос не отправляется, счетчик карточек не инкрементируется.
2. **Тест непрерывного свайпа 50 карточек под 4x CPU Throttling:**
   - Произвести серию из 20 быстрых свайпов влево и вправо.
   - Мониторить `requestAnimationFrame` delta: FPS не должен опускаться ниже 55 FPS, Long Tasks (>50 мс) должны отсутствовать.
3. **Тест анимации открытия/закрытия комментариев:**
   - Нажать кнопку комментариев на фото с высоким разрешением.
   - Замерить длительность первого кадра и плавность движения: шторка должна выезжать непрерывно за 300 мс без фризов в начале движения.
   - Закрыть свайпом вниз: закрытие должно происходить с естественной инерцией без белых вспышек.

## 5. КРИТЕРИИ ПРИЕМКИ (ACCEPTANCE CRITERIA)
1. **Zero False Swipes:** Никакие комбинации мультитача, зума и последующего отпускания пальцев не приводят к случайному смахиванию карточки или ложному голосованию.
2. **60 FPS Runtime:** При пролистывании колоды карточек и скролле ленты превью под 4x CPU замедлением частота кадров не падает ниже 55 FPS.
3. **Instant Comment Sheet Transition:** Открытие и закрытие комментариев происходит за фиксированные 300 мс без пропуска кадров и без ожидания загрузки полноразмерного фото.
4. **All Tests Passing:** Успешное прохождение e2e-тестов Playwright и unit-тестов бэкенда (`pytest`).
